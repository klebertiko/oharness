0.0.1-alpha.

Version 0.0.1-alpha is a pre-release of alpha quality: the app keeps changing, and the screenshots above show what exists today. The installers are not signed. Verify each file before you open it.

Open the 0.0.1-alpha release page

Before you download, check the system requirements: below them the interface renders broken, with no warning.

When the version is published, the files will be on its GitHub page. Pre-releases never show up under “Latest”, so the link points straight at the version. Until it is published, the page does not open.

Windows 10/11 x64OHarness-windows-x64-setup.exe

Unsigned. SmartScreen shows “Windows protected your PC” and an unknown publisher: choose “More info”, then “Run anyway”. Needs the WebView2 Runtime, present on current Windows 10/11.

macOS, Apple silicon and IntelOHarness-macos-arm64.dmgOHarness-macos-x64.dmg

Ad-hoc signature only, not notarized: Gatekeeper blocks the first launch. After verifying the file, use “Open Anyway” in System Settings, Privacy & Security.

Linux x86_64OHarness-linux-x86_64.AppImageOHarness-linux-amd64.deb

The system shows no warning. The AppImage carries an embedded GPG signature only if it is configured in this version's build; the .deb has no signature of its own. Needs glibc 2.35 or newer (Ubuntu 22.04+, Debian 12+).

Verify before you open

Also download SHA256SUMS and, in the same folder, check the checksum and the origin of the file (swap in the name of the file you downloaded):

bash
sha256sum --check --ignore-missing SHA256SUMS
gh attestation verify OHarness-windows-x64-setup.exe --repo klebertiko/oharness

On Windows (PowerShell), compare the hash with the file's line in SHA256SUMS: Get-FileHash -Algorithm SHA256 OHarness-windows-x64-setup.exe

The attestation proves where the file was built; it does not replace a publisher signature.

Known limits

  • The app window has an automated test on Windows only. On Linux and macOS, continuous integration builds and tests only the sidecar, the app's local service.
  • The app does not check the WebView version at startup, and the installer does not yet enforce a minimum (the declaration for macOS and the .deb is in PR klebertiko/oharness#167). See System requirements. Rendering varies between WebView2, WKWebView and WebKitGTK.
  • In the installed app, the database and secrets live in the app's local data folder, named after the identifier dev.oharness.app: on Windows, %LOCALAPPDATA%\dev.oharness.app; on macOS and Linux, the equivalent system folder.
  • There is no automatic update. Connected mode and the six connections exist, but this version does not claim that each one was tested end to end on every system.
  • Chat commands go through a broker in the backend, with path containment. In Ask mode every action asks for approval; in Auto mode only a fixed list of commands runs without asking. This does not isolate the operating system: what runs, runs with your privileges.
  • License: public preview, source available for evaluation; redistribution terms are not defined yet.

System requirements

What your
system needs.

The OHarness desktop draws its interface in the browser engine built into your system (the WebView). That is why the minimum depends on your operating system, not only on the app. Check it before you download; whatever was not verified is labeled “not verified”.

Below the minimum, the interface renders broken, with no warning.

The interface uses Tailwind CSS 4 (migration in PR klebertiko/oharness#120), which requires Chrome 111, Safari 16.4 or Firefox 128, or newer, because of @property and color-mix(). Source: the Tailwind documentation. On macOS and Linux the app uses the system's own WebView: if it is older than that, the layout breaks and the app shows no warning. On Windows, WebView2 follows the current Edge and meets the minimum.

Minimum requirements by system
SystemWhat it needs
Windowsx64

Windows 10 or 11, 64-bit (x64), with the WebView2 Runtime.

  • WebView2 is Microsoft's Evergreen runtime, which tracks Edge. Windows 11 includes it; on Windows 10, from version 1803 onward, the Tauri documentation says it is already installed.
  • If it is missing, the NSIS installer downloads the WebView2 bootstrapper and runs it. That needs an internet connection: without internet and without the runtime, the installer cannot install WebView2.
  • x64 only: there is no ARM installer. Windows 7, 8 and 8.1 do not qualify: their WebView2 stopped at Edge version 109, below the minimum.
macOSApple silicon and Intel

macOS 13.3 (Ventura) or newer, on Apple silicon or Intel.

  • Two native installers, one for Apple silicon (arm64) and one for Intel (x64). There is no universal installer.
  • 13.3 is the defensible floor: macOS 13.0 to 13.2 ship Safari 16.1 to 16.3, without @property.
  • Today this is documentation only. Declaring the minimum in the installer (LSMinimumSystemVersion) is in PR klebertiko/oharness#167 and only takes effect after it; until then macOS does not stop the app from opening on an older version.
Linuxx86_64

Linux x86_64 (64-bit), with WebKitGTK 2.40 or newer and glibc 2.35 or newer.

  • WebKitGTK: the package webkit2gtk-4.1 (libwebkit2gtk-4.1-0 on Debian and Ubuntu). 2.40 is a plausible floor, not a proven one (see “Not verified”). Ubuntu 22.04 without updates ships 2.36, below the floor; with security updates it reaches 2.50.x. As of October 2026: Ubuntu 24.04, 2.44 (2.52 with updates); Debian 12, 2.50; Fedora 42, 2.52.
  • glibc 2.35: Ubuntu 22.04+, Debian 12+ and Fedora 36+, according to the release workflow's comment.
  • The .deb depends on libwebkit2gtk-4.1-0 and, after PR klebertiko/oharness#167, on (>= 2.40). Before that the .deb does not require a version: apt installs it even with 2.36, and the interface may break.

Not verified

  • macOS: Apple does not literally state that “13.3 ships Safari 16.4”. That link comes from a secondary source (Eclectic Light).
  • macOS 12 and earlier: we did not verify whether an app's WKWebView gets a manually installed Safari 16.4. So we do not promise support.
  • macOS: the real minimum of the packaged binaries (the PyInstaller local service and native extensions) was not measured and may be higher than 13.3. We also did not verify exactly what macOS does when it opens an app below LSMinimumSystemVersion.
  • Linux: that WebKitGTK 2.40 is equivalent to Safari 16.4 and ships @property enabled by default. 2.40 was released on 2023-03-17 and its source already contains @property, but there is no official table that proves the equivalence.
  • Linux: does the AppImage carry its own WebKit? According to the Tauri bundler's code it does, but we did not check our file. The glibc requirement applies either way.
  • Linux: the effect of (>= 2.40) in the generated .deb (the package may appear twice in Depends) can only be confirmed in PR #167's file. The WebKitGTK version of Fedora 36 and of distros outside those listed was not verified either.

Included in the app

Four harnesses
to open and edit.

The desktop app bundles four harnesses. Open any of them in Studio as an editable copy; the original never changes. None comes with a provider set or with credentials: connecting is your choice. Today the app connects Anthropic and OpenAI through their local CLIs, OpenRouter with an API key, Ollama (local or cloud), and Cursor, for agents only.

The smallest is Agent + review: an agent, a review gate, and a human approval, in three nodes.

Agile Harness First in the app's list: an Agile/Scrum/Kanban harness, adapted from the engineering/harness skill. DeepSeek Harness Modelled on the desktop release dsh-v0.2.1-alpha.2: plan mode, the agent's turn and step loop, guarded tools, subagents, and goal continuation. Matt Pocock skills Modelled on mattpocock/skills: setup, grill, spec, tickets, TDD implementation, two-axis review, PR, human merge, and retro.

The last two are modeled on projects published by third parties. Their presence here does not indicate affiliation or endorsement.

OHarness Model

Your method.
In one file.

OHM is the document that describes a harness: who takes part, how work moves forward, and what content guides each role.

Readable YAML, a versioned structure, and the extension .ohm. Made to inspect, compare, and share without hiding the method inside an interface.

Explore the full structure

YAML is the format adopted for OHM. Desktop support is being migrated: the harnesses bundled in the app and the CLI use YAML, but Studio .ohm import and export still read and write JSON. The migration is decided, not implemented.

OHarness Manifesto

The future of agents deserves an open method.

We are building OHarness around a conviction: the way we work with artificial intelligence should be understandable, open to discussion, and carried forward by the people using it.

Read the full manifesto
A proposal taking shape.
An invitation to build it together.
  1. 01

    The method belongs to those doing the work.

    Your knowledge deserves to exist beyond the tool you chose today.

  2. 02

    What guides the work should be visible.

    Roles, instructions, and criteria need to be readable, reviewable, and open to discussion.

  3. 03

    Open connections expand your choices.

    Providers and tools may change. The intent of the work should remain understandable.

  4. 04

    Autonomy calls for clear limits.

    Explicit permissions, gates, and human authority are part of the method.

  5. 05

    Quality needs evidence.

    A result should be open to inspection. Trust is built through criteria and records.

  6. 06

    An open model evolves in public.

    Examples, criticism, and different implementations help improve what everyone can use.

These principles guide the project. They are not guarantees of completed features.

An ecosystem taking shape

Part of a
bigger conversation.

Prompts guide. Skills bring knowledge together. Context gives a task meaning. Protocols connect tools and agents. OHM proposes organizing these parts into a working method you can read, review, and share.

Prompt engineering Instructions, examples, and criteria to guide and evaluate responses. AGENTS.md Project context and conventions for coding agents. Agent Skills Reusable knowledge and procedures, packaged as skills. MCP Connections to tools and sources of context. A2A Communication and collaboration between agents from different systems. Agile Manifesto Collaboration, delivery, and adaptation as working principles.

Practices and specifications that help frame the ecosystem. Each has its role; inclusion here does not mean an integration is already available in OHarness.
