# OHarness v0.0.1-alpha

Pre-release. Not yet tagged; a maintainer tags and publishes after review. Assets: `OHarness-windows-x64-setup.exe`, `OHarness-linux-x86_64.AppImage`, `OHarness-linux-amd64.deb`, `OHarness-macos-arm64.dmg`, `OHarness-macos-x64.dmg`, `SHA256SUMS`, `OHarness-sbom.cdx.json` (see the [README](../../README.md#install)).

## Upgrading from OpenHarness

The product was renamed from OpenHarness to OHarness (#144). Compatibility paths are kept on purpose:

- **Tauri identifier** is now `dev.oharness.app`. The OS treats it as a different app: the old install and its per-app data are not picked up automatically.
- **Secrets folder** is `~/.oharness/secrets` when running unpackaged. If only `~/.openharness/secrets` exists it is still read from there (the file-store key depends on the path, so it is not moved). Keychain entries under the old `openharness` service are read through and migrated on first read.
- **Environment variables** are `OHARNESS_*`. `OPENHARNESS_BACKEND_URL` and the `OPENHARNESS_CURSOR_WSL_*` names still work as fallbacks. `OH_*` variables (`OH_SECRETS`, `OH_SECRETS_DIR`, `OH_DATA_DIR`, `OH_PORT`) are unchanged.
- The Automate and Pull requests screens and the `/automations` and `/repos` routes no longer exist (#31).

## Changes

### Rebrand
- Rename OpenHarness to OHarness across code, packaging and docs (#144).

### Redesign
- Every screen rebuilt on the OHarness design system (#141); design tokens, brand book, parity and contrast checks (#140).
- Studio: starting points as a scroll-snap rail (#106); auto-arrange graph, Agile Harness opens tidy ([ADR 0007](../adr/0007-graph-auto-layout.md), #107); file actions, Save as, Discard and Delete (#95); "Bundled harness" labels (#124).
- Two more bundled harnesses: DeepSeek Harness and Matt Pocock skills (#91); single vocabulary, "everything is a harness" (#103).
- Chat: per-conversation permission mode Ask / Auto / Plan, enforced in the backend (#102); collapsible activity summary (#99); turn ownership, model selection and Providers recovery (#136).
- Run history and versioned outputs are saved and survive restarts (#137).
- Desktop: Maximise button, drag and drop in Studio, single-instance conflict detection, taskbar and Nilo icon fixes (#96, #98, #64, #75-#79).
- Providers: Ollama local probe reports Unavailable on a running server's 404 (#81); Cursor delegation on Windows goes through WSL (#80).

### Sandbox
- Auto mode git hardening: inert git config only, nested repositories, `commondir`, `config.worktree`, `gitdir` and `info/attributes` fail closed, junctioned `.git`, git older than 2.32 gated, anchored operand grammars (#114, #121, #122, #125, #146).

### CI, release and supply chain
- Release workflow builds Windows, Linux and macOS installers into a draft release (#110); Pages publishes `website/` (#108); required checks also run in the merge queue (#94, #100).
- ESLint replaced by Biome (#119); Playwright e2e in CI (#111); OWASP NVD cache (#116); Gitleaks and SBOM fixes (#131, #143); cargo-audit 0.22.2 (#67).

### Dependencies
- Grouped frontend, backend and Tauri/Rust bumps (#60, #62, #129, #133, #134); `filelock` 4.2.4 for CVE-2026-112940 (#169).

## Known limits
- Builds are provenance-attested but not production-signed; see [CI & security](../ci-security.md).
- Import and Export in Studio still use JSON text inside `.ohm`; see [YAML migration](../product/ohm-yaml-migration.md).
- Laya, the local classifier, is experimental.
